## 五、必须知道的三个约束

1. **来源字段为空是刻意为之，不是遗漏。** 离线状态下 7B 模型给出的 QID/URL 属记忆幻觉，写入即构成伪造来源（违反项目 README 第 5 节）。若确实需要模型猜测值做对比实验：`--qid-policy model` 重跑即可，但产出不可作为交付数据。

2. **关系边不建议继续调 prompt。** 已做 4 轮 prompt 迭代，结果是「按下一处、翘起另一处」，且同一 prompt 重跑结果会漂移；更反直觉的是加入「不要填学科分类名」的显式指令后，模型反而开始编造非分类的错误上位。**100 条规模下人工复核（约 20 分钟）比继续调 prompt 更快更稳。**

3. **跨批悬空引用是设计内的正常状态。** 69 条 parent 指向本批次外概念，是因为 100 条清单本身就是更大知识图谱的子集；补齐后续批次后这些边会自动闭合，**不是数据缺陷**。

## 六、对下一阶段（衍生 AI 评测集）的建议

1. **先冻结关系边策略再入图**：建议采用「人工复核后写回」的双轨制——文案字段（definition/formula）直接沿用模型输出；关系字段以人工校订值为准，并在记录中增加 `edge_verified: true/false` 标记，便于评测集区分可信与待核边。
2. **评测集不要沿用本批的关系边作为 ground truth**。48.4% 的闭合率意味着用它做知识图谱推理评测会引入大量噪声标签。建议评测集的关系边全部走人工标注或外部权威知识库校验。
3. **扩批时保持 `format=json` 与 `--qid-policy null`**，二者分别保证 100% 零污染与来源可追溯。
4. 吞吐可线性外推：**约 1.94 s/条、42.4 tok/s**，1000 条约 32 分钟（单机 RTX 4060 Laptop，无需分批调度）。
